04 / RUN PATROL

运行巡检，自动保存证据

从 Skill 文件夹运行。默认写入 amazon-patrol-output 且不发送飞书；批量巡检会保留失败位置并继续后续市场，存在失败时退出码为 1。

A

巡检单个市场

将 <店铺ID> 替换为目标店铺，将 us 替换为所需市场代码。

PowerShell
python scripts\amazon_account_patrol.py `
  --store-id <店铺ID> `
  --marketplace us
B

巡检全部九个市场

某站失败会保留原因并继续后续市场；存在任何失败时退出码为 1。

PowerShell
python scripts\amazon_account_patrol.py `
  --store-id <店铺ID> `
  --all-marketplaces
C

限定巡检时间

只有业务明确要求时才使用。时区与时间窗口必须一起提供。

PowerShell
python scripts\amazon_account_patrol.py `
  --store-id <店铺ID> `
  --marketplace uk `
  --timezone Europe/London `
  --working-hours 09:00-18:00
D

可选：推送到飞书

必须由用户明确要求，并先配置飞书凭证。API 未返回成功时不得声称已发送。

PowerShell
python scripts\amazon_account_patrol.py `
  --store-id <店铺ID> `
  --marketplace de `
  --send-feishu `
  --feishu-chat-id <群聊ID>

05 / OUTPUT & GUARDRAILS

输出什么，什么算完成

脚本成功表示站点核验通过、两页实际 URL 与原文已写入 Markdown、两张截图路径非空且文件存在、时间戳日志已生成，并在终端末尾输出结果 JSON；可选飞书以返回的 message_id 证明 API 已受理。

Markdown 记录<store>-<MARKET>-YYYY-MM-DD.md两页实际 URL 与原文、摘要、建议及截图路径；同日重跑会覆盖
双页截图health + notifications脚本要求 CLI 返回两张全页截图，并验证路径非空且文件真实存在
时间戳日志logs/<store>-<stamp>.log记录每一步操作、失败位置与准确错误
终端结果stdout 末尾 JSON + exit 0 / 1没有独立 result.json；飞书受理时返回 message_ids，任一失败返回 1
运行护栏

只使用目标紫鸟店铺自身保存的 Amazon 登录态。

不手工输入或传递邮箱、密码与 OTP。

不修改商品、价格、库存、广告或账户设置。

市场切换后核对工作台路径、国家标签，以及目标域名或 marketplace ID。

停留在 account-switcher 时只重试一次确认，不盲点。

本地记录不等于飞书受理；必须同时取得 code 0 与 message_id。

每次只巡检一个店铺会话，不输入其他店铺信息，避免账号关联风险。

OTP 缺失或过期立即停止当前市场。不要手工输入，不要重复提交旧验证码，也不要用无限等待代替重新获取有效值。
